1Project Title

SnakeAI — Space Edition
A fully browser-based Snake game built entirely using AI assistance, featuring a Space Galaxy theme, Math Challenge Mode, procedural audio, 4 power-ups, 3 difficulty levels, and a persistent leaderboard.

2App / Game Idea

The project is a modern reimagining of the classic Snake game, redesigned with a space exploration theme. The player controls a snake-like spacecraft moving across a starfield canvas, collecting glowing planets as food while avoiding walls. The game escalates in difficulty and introduces power-ups that change speed, multiply score, or protect against wall collisions.

A unique addition — the Math Challenge Mode — overlays math questions onto the game, turning each food collection into a learning moment. The food planet displays the correct answer to an arithmetic question shown in the HUD. This transforms a casual game into an educational tool.

Classic Snake Mechanics Space / Galaxy Theme 4 Power-Ups Math Challenge Mode Leaderboard Procedural Music Mobile Support

3Purpose of the Project

The primary purpose was to demonstrate AI-assisted development by building a fully functional, polished game from scratch using only natural language prompts to an AI coding assistant. The project aimed to:

  • Practice prompt engineering through multiple iterations
  • Learn how AI tools can accelerate game development
  • Explore the capabilities of Canvas 2D, Web Audio API, and localStorage in a browser environment
  • Build something visually engaging and genuinely replayable
  • Demonstrate real-world educational value through the Math Challenge Mode
The game was entirely contained in a single index.html file with zero external dependencies beyond Google Fonts — proving that a polished browser game can be shipped without a build system or framework.

7What Worked Well

  • Single-file architecture — keeping everything in one index.html made iteration fast. No build step, no config files, instant feedback in the browser.
  • Canvas 2D rendering — the AI-generated drawing code was accurate and produced a visually polished result immediately, including gradient fills, radial glows, and shadow effects.
  • Web Audio API procedural music — generating ambient space music without any audio files was surprisingly effective. The low-frequency drone with LFO modulation creates a genuine atmosphere.
  • Iterative refinement — each prompt built on the last. Describing exactly what to change (not what to rebuild) allowed features to accumulate without losing prior work.
  • AI understanding of game logic — complex systems like the direction queue (preventing 180° reversal), particle systems, and the power-up timer bar were implemented correctly on the first attempt.
  • Responsive design — scaleCanvas() and CSS flexbox layout made the game work on all screen sizes without additional prompting.
  • localStorage leaderboard — persistent scores across sessions were implemented cleanly with JSON serialization, XSS escaping, and top-10 capping.

8What Did Not Work

These are areas where the AI-generated code required correction or where the initial approach failed.
  • 180° reversal bug — the first version allowed the snake to immediately reverse direction, killing itself. The AI's first fix (checking dir instead of the queued ndir) was incorrect and required a follow-up prompt to implement a proper direction queue.
  • Power bar persistence — the power-up HUD bar was not being reset on game restart, meaning visual state leaked from one game session into the next.
  • Self-collision regression — the v3.1 fix explicitly removed self-collision, but the v4.0 complete rebuild accidentally re-introduced it. Regressions like this happen when doing full rewrites rather than incremental changes.
  • Automated screenshot testing — the Playwright snake automation script moved the snake into walls immediately, producing a score-0 game-over screenshot instead of a live gameplay shot. Required multiple attempts with slower timing and easy difficulty.
  • Wall Shield timer UX — the original HUD timer bar for the SHIELD power-up stayed at 100% permanently (since shield is consumed on first use, not on a timer). This confused the intent and required an explicit fix to show "1 USE" instead.

10How Issues Were Solved

Bug 1 — 180° Reversal

Solved by replacing the single dir check with a direction queue (max 2 entries). New inputs are only accepted if they don't oppose the last queued direction, not the currently active direction. This prevents the race condition where two keys could be queued and applied in the same tick.

Bug 2 — State Persistence Between Games

Solved by adding explicit reset calls in initGame(): clearing the power bar display, resetting fill widths to 100%, and hiding HUD elements before each new game session begins.

Bug 3 — Fruit Speed Boost

Solved by making getMs() (the function that returns the move interval in milliseconds) read from both the active power-up state and the fruit boost flag simultaneously, combining their effects on the base interval.

Bug 4 — Particle FPS Drop

Solved by capping the global particle list at 180 particles maximum and limiting power-mode sparkle emission to the head + 4 segments only. This kept particle counts bounded at any snake length.

Bug 6 — Self-Collision Regression

Solved by removing the snake.some() check in tick() that was re-introduced during the v4 rebuild. Only wall boundary collision now triggers game over, restoring the v3.1 design intent.

Bug 7 — Shield HUD

Solved by modifying showPuHud() to detect when SHIELD is the active power-up and replace the timer bar with a "1 USE" text label. The hidePuHud() function was updated to restore the timer bar on exit.

Bug 10 — AudioContext Autoplay Policy

Addressed by only calling audio.init() inside the Launch Mission button click handler — ensuring the AudioContext is created and resumed after a confirmed user interaction, as required by browser autoplay policies.

11Features Added or Improved

Core Game

  • Classic snake movement on a 30×22 cell grid (600×440 canvas)
  • 3 difficulty levels: Easy (170ms/move, ×1), Medium (115ms, ×1.5), Hard (72ms, ×2)
  • 3-2-1-GO! animated countdown before each game
  • Pause (P / Space / Esc) and mute (🔊) toggles in HUD
  • Player callsign input, persisted to leaderboard

Visual System

  • Two-layer animated starfield (220 background stars + 120 in-game stars)
  • 4-corner nebula gradients in the game canvas
  • Planet food with radial gradient fill, specular highlight, and optional orbital ring
  • Snake rendered as a comet trail — RGB gradient from head to tail, rounded connectors, glowing eyes
  • Particle explosion system on food collection (18 particles) and game over (60 particles, dual colour)
  • Canvas auto-scales to viewport size on load, resize, and retry

Power-Up System

  • ⚡ Speed Boost — cuts move interval to 52% of base for 5 seconds
  • ❄ Slow Motion — stretches move interval to 185% for 6 seconds
  • ✦ 2× Score — doubles all points earned for 8 seconds
  • ◈ Wall Shield — absorbs one wall collision (snake wraps through instead of dying)
  • Power-ups spawn every 13–21 seconds and vanish after 9 seconds if uncollected
  • Orbital dot animation and shrinking timer arc on uncollected power-ups
  • HUD shows active power-up name, icon, and countdown bar (or "1 USE" for Shield)

Leaderboard

  • Top 10 scores stored in localStorage with name, difficulty, and date
  • Shown on both start screen and game over screen
  • "★ NEW HIGH SCORE ★" badge when topping the leaderboard
  • XSS-safe rendering using HTML entity escaping

Audio

  • Procedural ambient music: 3 low-frequency drones (55Hz, 82Hz, 110Hz) with LFO modulation + Am chord pad, fully synthesised via Web Audio oscillators
  • Sound effects: eat (frequency sweep), power-up (ascending arpeggio), expire (descending), game over (sawtooth descending scale)

Math Challenge Mode (Phase 2 Addition)

  • Optional toggle on start screen — does not affect normal gameplay when off
  • Green HUD bar shows current question (e.g. "SOLVE ▸ 7 × 8 = ?")
  • Correct answer displayed as white text on food planet surface
  • Toast confirms full equation on each food collection (e.g. "✓ 7 × 8 = 56")
  • Questions scale with difficulty: addition (Easy), multiplication (Medium/Hard)

Mobile Support

  • On-screen D-pad (auto-shown when screen width < 700px or mobile user agent)
  • Touch swipe on game canvas (minimum 8px threshold)
  • Responsive canvas scaling with clamp() font sizes

13Real-World Problem Solved

Problem: Students often find math drills boring and struggle to stay engaged with repetitive arithmetic practice exercises.

Solution: Math Challenge Mode

The Math Challenge Mode transforms the game into a gamified math drill tool. Rather than sitting through worksheets, students practice arithmetic facts naturally — each time the snake eats food, a new question is answered. The game loop (eat → score → grow → eat) creates a motivating feedback cycle.

How it addresses the problem

  • Engagement — Students are motivated to keep playing, which means more math facts practiced per session compared to worksheets
  • Spaced repetition — New questions generate randomly on each food spawn, providing varied exposure across a session
  • Difficulty scaling — Easy mode covers addition for younger students; Medium and Hard cover multiplication for more advanced learners
  • Instant feedback — The toast message ("✓ 7 × 8 = 56") confirms the correct answer immediately after each collection, reinforcing the fact
  • Zero friction — No login, no app install. Students open a browser link and start learning immediately

Target users

  • Primary school students (ages 7–12) practicing addition and multiplication tables
  • Teachers looking for a free, browser-based math game with no ads
  • Parents wanting a productive screen-time activity
The game is free, open source, works on any device with a browser, and requires no account or installation — making it immediately accessible for classroom or home use.
